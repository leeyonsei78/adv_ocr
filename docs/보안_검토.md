## 3. 반입 구성요소 (공급망)
- 파이썬 패키지는 `requirements-offline.txt` 에 버전을 고정(paddlepaddle 3.3.1, paddleocr 3.7.0, paddlex 7.2 등). 반입 시점의 CVE 점검과 사내 백신 검사를 받으세요.
- OCR 모델(`models/`, Apache-2.0, 약 18MB)은 PaddleOCR 공식 배포본입니다. 모델 파일은 pickle 이 아닌 Paddle 추론 형식이지만, 출처 해시를 확인해 반입하세요.
- LibreOffice(PPTX 슬라이드 렌더링용)는 묶음에 포함하지 않습니다. 설치한 경우 신뢰할 수 없는 PPTX 를 처리하는 공격면이 커지므로 격리 계정/샌드박스에서만 쓰세요(없어도 텍스트·삽입 이미지 OCR 은 동작).

## 4. 남은 위험과 운영 권고
1. **전송 구간 암호화 없음(http)**: 사내망 공유 시 https 종단 프록시(예: 사내 표준 리버스 프록시)를 앞에 두고 `ADREVIEW_SECURE_COOKIE=1`. 본인 PC(127.0.0.1) 사용은 해당 없음.
2. **비밀번호 관리**: 환경변수 또는 `config/run.env` 에 평문으로 둡니다. run.env 는 서비스 계정만 읽도록 파일 권한(ACL)을 제한하고, 사내 계정(SSO/AD) 연동이 필요하면 별도 개발이 필요합니다. 계정별 개인 인증이 아니라 공용 비밀번호 + 이름 입력 방식이라 **감사 로그의 이름은 자기 신고**입니다.
3. **접근 통제**: 서비스 포트(기본 8080)는 방화벽으로 허용 대역만 열고, 전용 서비스 계정(일반 사용자 권한)으로 실행하세요. 관리자 권한으로 실행하지 마세요.
4. **데이터 분류**: 결과 폴더(`output/web/`)에는 광고 이미지와 검수 결과가 남습니다(개인정보는 의도하지 않음). 사내 정보자산 분류에 맞는 저장 위치·암호화·보관기간을 정하세요. 광고 원본에 고객 정보가 섞일 수 있는 경우 업로드 금지 기준을 정하세요.
5. **서비스 거부**: 인증된 사용자만 업로드할 수 있고 크기·장수 상한이 있으나, OCR 은 한 번에 한 건씩 처리하므로 대용량 요청이 몰리면 대기가 길어집니다. 동시 사용자가 많으면 별도 서버로 분리하세요.
6. **로그 보존**: `audit.log` 는 파일 기록(변조 방지 없음)입니다. 필요하면 사내 로그 수집 체계로 주기적으로 이관하세요.
7. **기준 변경 통제**: 기준 저장은 즉시 이후 검수에 반영됩니다. 승인 절차(변경 요청 → 검토 → 반영)는 업무 프로세스로 따로 두세요. 모든 변경은 `config/history/` 에 백업·이력이 남습니다.
8. **의존 패키지 갱신**: 폐쇄망에서는 자동 업데이트가 없으므로 취약점 공지 시 반입 묶음을 새로 만들어 교체하는 절차를 정해 두세요.
9. **본 도구의 판정은 1차 보조**이며, 오탐·미탐이 있습니다. 심의 결과의 최종 책임은 담당자에게 있습니다.
